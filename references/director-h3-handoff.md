# 导演分镜与 H3 提示词交接

## 加载实际 Skill

默认分镜依赖为 `cinematic-director`，H3 提示词依赖为 `h3-prompt-writing`。优先用当前 Skill 目录解析；同级安装时分别读取 `../cinematic-director/SKILL.md` 和 `../h3-prompt-writing/SKILL.md`（路径相对本 Skill 根目录）。上游文件、版本和安装提交见 `upstream-sources.json`；实际每次调用记录本次读到的版本／SHA，不能把安装记录当成设计执行或视频生成回执。

两个上游 Skill 的指令正文保持原文，沿其引用读取相关参考。仅为兼容本机 Codex 校验，H3 的顶层 `compatibility` 说明移入 `metadata.compatibility`；上游原件与本地差异记录在来源文件中。`cinematic-director` 的 MIT 版权和许可证保留在原目录；H3 的提示词内容保留原来源。不把其说明复制到本文件形成第二套模型规范。

## 故事输入

向导演 Skill 提供以下本期信息，已有值直接复用，缺失值说明：

```text
故事范围与正式标题：
关键人物、当时身份与关系：
有依据的处境、行动、地点、物件及来源 ID：
```

## cinematic-director 的本期产物

先按[片头口播与画面联动](narration-picture-design.md)给出口播语义与视觉节拍，再执行适用的C/D/G/E；未配音时是分镜预案，音轨就绪后按真实cue回定：

- **口播—画面对应表**：实际朗读原句／来源、信息功能、人物状态与时代意象、镜头／转场、估时或真实cue、动画末句与正文接句；不固定一句一镜，不用参考片秒数机械压缩口播。
- **角色卡**：身份依据；从已锁参考读取的脸、须发、发式、衣冠；冻结的身份描述；表演用可见身体变化表达，不能只写“威严”“克制”。
- **人物 prompt**：片头有人物时，按[人物设定到生成提示词](character-prompt-design.md)把每位主要人物的特征／可见状态写成基础描述及逐镜图片、视频描述，附角色ID→镜头→实际参考→H3人物标签映射；不以角色卡或姓名题签代替进入实际请求的人物 prompt。
- **场景卡**：有据地点与时代，美术示意的建筑／道具；人物左右、距离、出入口和固定地标；无人场景图未生成时只称场景设计卡。
- **镜头表**：按上游 D 模板填写故事功能、时间、景别、机位、等效镜头感、单一镜头运动、人物起→动→末态、连续性锚、转场载体和难度。镜头数量随故事和时长决定。
- **接点**：A 镜末态、B 镜初态、主体在画面的位置、运动方向、视线、衣冠与物件状态、墨色／光位；进入正文时还给出原音轨 cue 与首幅静图运镜相位。

需要角色、场景或首尾帧图像时加 E 并输出该图的独立提示词及所需参考；实际调用本项目生图通道，设计卡不冒称已生成图像。分镜板可供审阅，带格线与文字的整板不能直接当最终首帧。存在已验收且适合本镜的素材时复用；人物脸可辨的镜头须有适用的角色／关键帧依据。

**本工作流的覆盖关系**：历史证据和本期图像锁约束导演创意；中式二维水墨约束材质，不套真人摄影或 3D 默认风格。等效焦段用于说明透视和景别。上游的重试预算不增加本片额度；已有项目验收仍按该通道现行规则，不额外要求用户逐张重新确认。H3 支持并且本次选用连续多镜模式时，动作和运镜预算按每镜评估，不能把多镜写成一条无终态的复合动作。未点名导演时不强加某位导演的风格。

## 历史剧片头蒙太奇

`sequence_form: title_sequence` 的导演 C 模式先定义**时代尺度、人物特征、镜头行进方向和转场载体**；再由 D/G/E 落实镜头、身份与关键帧。故事用于选择时代和人物母题，不强迫片头复演某一幕剧情。

- **时代背景**：选择本期适用的山河、城郭、宫阙、军阵、河道或器物。用前景遮挡、中景建筑和远景山河建立纵深，避免把大场面压成室内浅墙或缩略图拼贴。抽象纹理不充当精确地图，跨地点／跨时代叠映注明象征合成。
- **人物层**：用可辨的肖像、轮廓、眉眼、须发、衣冠和姿态体现特征；优先稳定脸部、手不成为转场细活。前景肖像可以大于远景建筑，明确它是片头的美术叠映而非真实巨人或真实共同现场。年龄阶段按故事选择，不从参考片演员借脸。
- **转场**：每个接点只选一个主要载体，例如一束云雾沿固定方向掠过并揭开下一层、衣袍墨影与下一镜山脊形状匹配、旌旗边缘遮挡接下一幕。载体必须在关键帧布局中存在，定义遮挡区间、出入方向、后景显现和人脸保护；不能只写“史诗感”“蒙太奇”或“丝滑转场”。跨景虚拟机位可同向穿行，避免把人物变脸或衣冠变形当转场。
- **正文接点**：末镜把人物、轮廓、墨色、视线或时代母题交给正文，不要求象征片头与正文共享同一真实房间。实际接片仍核人物身份、时代及原音轨／字幕时钟；允许场所变化不等于允许换脸。

用户给参考视频时区分：实际画面/可见转场、发布标题、作者文字、评论及效果数据。参考没有人物时，不虚称它演示了人物肖像；人物层来自用户要求及本期设计。参考的所有朝代、地图、题字、色彩和时长均不是新片配额；只迁移已观察且符合本期需求的视觉方法。材质继续服从用户所选风格，空间分层不自动切成写实真人或3D卡通。

## 关键帧先行

当人物状态、明确画风和跨镜连续性是主要诉求时，先把 E 模式的设计落实为可用图片，再编译视频请求：

1. **查看所选风格样本**。从用户点名的视频实际采用区间读出浓淡关系、墨块边缘、飞白、纸色、人物尺度、背景层次和少量色彩的位置。借用这些材料与构图方法；人物、须发、时代衣冠、地点和道具仍取本期故事及正文。风格来源存在文字或字幕时，记录它们属于后期，不让生图模型照画。
2. **首帧确定美术方向**。优先生成一张主体可辨、具有动作起态的独立全幅画面。继续同一空间时，以这张图和角色依据派生后续关键帧；工作台真实支持图生图编辑才使用其实际参考绑定。文生图仅把作者观察转为文字时，如实标记未上传图像参考；相同种子不能称为锁脸。
3. **覆盖不同镜头及正文接点**。每个切镜明确引用适用画面；不能用一张双人全景同时冒称两张人物近景的已生成首帧。人物动作承担转场时先设计前镜末态与后镜初态的袖缘位置、运动方向和脸部可见区；末镜须与正文首画面核身份及位置。首尾帧配对只在同一镜头内解决可插值变化，不强迫两个不同景别连续形变。
4. **按项目现行通道检查并锁定**。新风格／参考组合按所在项目的版本化校准执行。Studio API 的 `api-direct-v1` 只做其规定的来源和技术检查，不额外调用 GPT 视觉审图或伪造审美分数；已有参考观察、提示词设计与后续视频动态检查分开记录。用户要求先看图时交关键帧供其判断；默认不增加逐图人工审批。
5. **按实际视频能力接入**。单镜首帧用 I2VA；多镜、多个参考可用 Ref2VA，但参考图和提示词切点不等于逐镜硬绑定；模型未实现计划切点时以实绩记录为准。需要更精确的镜头控制时，在本期授权与时长能力内逐镜图生视频并本地剪接。只有工作台真正提供首／尾帧输入槽时才使用 FL2VA，不能把普通参考上传误写为首尾帧控制。

保留关键帧清单：镜头 ID、首态／末态用途、风格来源、身份来源、实际上传顺序、原件和 SHA、生成模式、真实任务回执及适用验收。`keyframe_prompts_ready` 与 `keyframes_generated` 分开；先看文字分镜或现有正文图不等于新水墨关键帧已经产生。视频提示词依据最终使用的关键帧重编译，不沿用旧图描述。

## h3-prompt-writing 的本期产物

将镜头表、固定身份描述、参考清单和声音处理交给官方 Skill，先按工作台实际模式选择指南：

| 实际输入 | 读取的官方参考 | 输出 |
|---|---|---|
| T2VA、I2VA、FL2VA、L2VA | `references/base-en.txt` | `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music` |
| Ref2VA 多图／多模态参考 | `references/ref-en.txt` | `subject_definitions`、`summary`、`retention_analysis`、`detailed_description`、`overall_soundscape`、`non_diegetic_music` |

六段式的键名、顺序、任务类型前缀、保留度标记及参考标签均按官方指南；H3 官方指南及本地接口能力高于导演 Skill 中的泛用 Hailuo 适配说明，不自动加入其旧式方括号相机命令。首镜用 `[Shot 1]`，后续切点用 `[Shot N] At MM:SS.mmm, ...`；正文用英文，真实对白和歌词保留原语言。准确题签与口播字幕在本地排版，模型画面保持无字。只用实际提供的参考标签，不给未上传的音轨／视频虚构 `<Audio N>` 或 `<Video N>`。

记录两类分开的文件：

1. `h3-prompt.json`：官方字段原文，便于检查和按序组装。
2. `video-request-plan.json`：模型、模式、原提示词文件／SHA、参考顺序和各文件 SHA、时长／尺寸／质量、真实授权／剩余额度、自动改写及待查能力。它是请求准备；提交后另保存真正的任务号和生效回执。

对每个切点核起末态和累计时长，对每个 `<Picture N>` 核参考顺序和文件。官方当前指南的生成时长为 4—15 秒；遇到超范围或本地工作台不同限制先按真实能力重新分段／裁切设计，不暗中拉伸、冻结尾帧或更改原音轨。参数示例不代替实时接口。

## 交给本期工作台

只读取并遵循这两个 Skill 就可在 Codex 内产出设计与提示词；生成能力来自用户选定的工作台。读取项目调用规范和可用 API／CLI 适配器，核其登录、真实模型与模式、参考绑定、尺寸和提示词是否会自动改写。正式提交仍按本次范围和有效授权执行；返回未知状态查询原任务。设计任务停在请求包，试片任务取回实际原片并检查，接片任务再按 `body-handoff.md` 制作连续预览。
